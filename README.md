Aspetos a serem considerados:
• separação das camadas logica e UI
• utilizar polimorfismo e reduzir dependências através de interfaces/classes abstractas
• classes coesas e com encapsulamento (sem sets e com gets como o getPosition, em vez de
getX e getY)
• distribuição do código por diversas classes (não ter classes muito grandes; pequenas não são
problema, desde que se justifiquem, como por exemplo interfaces)
• main relativamente pequena e que permita perceber o funcionamento e lógica principal do
jogo
• segurança (e.g., testar situações de erro, const), eficiência (e.g., não duplicar chamadas de
funções, usar referências), ausência de repetições (e.g., ciclos em vez de linhas muito
parecidas)
• nomes de classes e funções adequados
• utilizar excepções
• funcionamento independente do PC utilizado
